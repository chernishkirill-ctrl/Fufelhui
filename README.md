# Telegram CRM для агентства недвижимости

Внутренняя CRM агентства с интерфейсом в Telegram. В ней есть:

* личный пульт владельца;
* кабинеты риелторов;
* общая база объектов с историей;
* рабочий чат с Topics;
* архив;
* заявки клиентов с механизмом «первый забрал клиента»;
* сделки и комиссии;
* публичный канал и Telegraph;
* ежедневные отчеты и статистика;
* импорт объектов по ссылке.

Стек: Python 3.11, aiogram 3, PostgreSQL, SQLAlchemy 2 (async), Alembic, APScheduler, httpx и BeautifulSoup.

Подробная архитектура описана в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md): модели и связи, права, FSM, callback-и, Topics, импорт, публикация, заявки, сделки, отчеты и анализ гонок.

## 5. Локальный запуск

```bash
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt

cp .env.example .env              # заполните BOT_TOKEN, OWNER_ID, DATABASE_URL, BOT_MODE=polling
set -a && source .env && set +a   # или используйте direnv / IDE

alembic upgrade head              # создать таблицы
python -m bot.main                # запуск в режиме polling
```

Для быстрой пробы без PostgreSQL подойдет `DATABASE_URL=sqlite+aiosqlite:///./crm.db`. Для продакшена нужен только PostgreSQL.

Тесты и линтер:

```bash
pytest                                                            # SQLite
TEST_DATABASE_URL=postgresql+asyncpg://user:pass@localhost/crm_test pytest   # на PostgreSQL (включая тест гонки)
ruff check bot
```

## 6. Деплой на Render

Рекомендуемый вариант — Blueprint.

1. Запушьте репозиторий на GitHub.
2. В Render Dashboard выберите **New → Blueprint** и укажите репозиторий. Render прочитает `render.yaml` и создаст web-сервис `realty-crm-bot` и базу `realty-crm-db`.
3. Заполните секреты, помеченные `sync: false`: `BOT_TOKEN`, `OWNER_ID`, `WORK_CHAT_ID`, `PUBLIC_CHANNEL_ID`, ID тем (можно оставить пустыми, см. п. 9) и `AGENCY_NAME`. Значения `WEBHOOK_SECRET` и `CRON_SECRET` сгенерируются сами.
4. **Apply.** При каждом деплое:
   * `pip install -r requirements.txt`;
   * `alembic upgrade head` (preDeploy, до переключения трафика);
   * `python -m bot.main`.

Режим работы на Render — **webhook**. Render сам задает `RENDER_EXTERNAL_URL`, и бот регистрирует `https://<сервис>.onrender.com/telegram/webhook` с `secret_token`. Keep-alive-пинги не используются. Health-check: `GET /health`.

**План.** В `render.yaml` указан `starter` (always-on), потому что встроенный планировщик должен сработать в 22:00.

На бесплатном плане сервис засыпает. Входящие апдейты его будят (webhook), но запросы отчетов по расписанию могут не отправиться. Если все же нужен бесплатный или засыпающий план, создайте Render **Cron Job**, который в нужное время делает:

```bash
curl -fsS -X POST -H "X-Cron-Secret: $CRON_SECRET" https://<сервис>.onrender.com/cron/report-reminders
curl -fsS -X POST -H "X-Cron-Secret: $CRON_SECRET" https://<сервис>.onrender.com/cron/report-summary   # через ~1.5 ч
```

Повторные вызовы безопасны: в один день рассылка уходит только один раз.

**Ручная настройка без Blueprint:**

1. Создайте PostgreSQL.
2. Создайте Web Service:
   * Build `pip install -r requirements.txt`;
   * Pre-Deploy `alembic upgrade head`;
   * Start `python -m bot.main`;
   * Health Check Path `/health`.
3. Задайте переменные из `.env.example`. `DATABASE_URL` — это Internal Database URL базы.

> Названия планов Render (`starter`, `basic-256mb`) могут меняться. Если Blueprint их не примет, выберите актуальные в интерфейсе.

## 7. PostgreSQL

* **Render:** New → PostgreSQL (или через Blueprint). Скопируйте **Internal Database URL** в `DATABASE_URL`. Формат `postgres://…` приводится к `postgresql+asyncpg://…` автоматически.
* **Локально:**
  ```bash
  createuser -P crm && createdb -O crm crm
  export DATABASE_URL=postgresql://crm:<пароль>@localhost:5432/crm
  alembic upgrade head
  ```
* **Резервные копии:** на платных планах Render делает бэкапы автоматически. Вручную можно так: `pg_dump "$DATABASE_URL" > backup.sql`.

Все данные (пользователи, объекты, заявки, сделки, отчеты, история, настройки) хранятся в PostgreSQL и переживают перезапуски и деплои.

## 8. Какие Telegram ID нужны

| Что | Переменная | Как узнать |
|---|---|---|
| Ваш user ID (владелец) | `OWNER_ID` | @userinfobot (или `/id` в боте после первого запуска) |
| ID рабочей супергруппы | `WORK_CHAT_ID` | добавить бота в группу, написать `/chatinfo` (от владельца) → `chat_id` (вида `-100…`) |
| ID тем «База», «Архив», «Сделки», «Чат», «Заявки» | `BASE_TOPIC_ID`, `ARCHIVE_TOPIC_ID`, `DEALS_TOPIC_ID`, `CHAT_TOPIC_ID`, `LEADS_TOPIC_ID` | `/chatinfo` внутри каждой темы → `message_thread_id`, либо создать темы кнопкой в ⚙️ |
| ID публичного канала | `PUBLIC_CHANNEL_ID` | `@username` канала или `-100…` (переслать пост из канала @userinfobot) |
| ID риелторов | — (хранятся в БД) | риелтор пишет боту `/id`, либо используйте ссылку-приглашение |

## 9. Настройка рабочего чата и Topics

1. Создайте группу, в настройках включите **Topics (Темы)**. Группа станет супергруппой.
2. Добавьте бота администратором с правами: отправка и удаление сообщений, **управление темами**.
3. Укажите чат одним из способов:
   * задайте `WORK_CHAT_ID` в окружении;
   * или напишите `/bindchat` в группе от имени владельца.
4. Темы можно настроить любым из способов:
   * **автоматически:** в боте ⚙️ Настройки → «🧵 Создать темы в рабочем чате». Будут созданы 💬 Чат, 🏠 База, 📦 Архив, 🤝 Сделки, 📋 Заявки;
   * **вручную:** создайте темы сами, в каждой напишите `/settopic base` (`archive`, `deals`, `leads`, `chat`);
   * **через env:** `/chatinfo` в каждой теме, затем заполните `*_TOPIC_ID` на Render (значения из env имеют приоритет).
5. Если в группе включен «Privacy mode» бота, выключать его не нужно: бот реагирует только на команды и нажатия кнопок. На обычную переписку в теме «Чат» он не отвечает.
6. В боте нажмите ⚙️ → «🩺 Проверить подключение». Бот покажет, видит ли он чат и канал, есть ли права администратора и включены ли Topics.

## 10. Публичный канал

1. Создайте канал (публичный с @username или приватный).
2. Добавьте бота администратором с правами **публикации и удаления сообщений**.
3. Задайте `PUBLIC_CHANNEL_ID` (`@username` или `-100…`).
4. Проверьте: ⚙️ → «🩺 Проверить подключение», затем опубликуйте тестовый объект из его карточки.

Кнопка «📅 Записаться на просмотр» в постах ведет в личку с ботом (`https://t.me/<бот>?start=lead_<id>`), поэтому клиент попадает прямо в анкету.

**Команды в рабочем чате (только владелец):** `/chatinfo`, `/bindchat`, `/settopic base|archive|deals|leads|chat`.

## 12. Реализованные функции

- [x] Доступ владельца только по `OWNER_ID` (env). Роли owner, realtor и admin (зарезервирована). Права проверяются на сервере в каждом обработчике, fallback отвечает «Доступ запрещен.»
- [x] Добавление риелторов по ID и по одноразовой ссылке. Блокировка, удаление без потери истории.
- [x] Объекты: ручное добавление (мастер), импорт по ссылке (OLX, DOM.RIA, любой сайт), поиск, карточка, редактирование 18 полей, фото, 8 статусов, ответственный, удаление (запрещено при наличии сделок), полная история.
- [x] Приватные поля (собственник, телефон, внутренний комментарий, адрес) никогда не попадают в канал и Telegraph.
- [x] Рабочий чат с Topics: карточки в «База» (обновляются), «Архив», «Заявки», «Сделки». Тему «Чат» бот не трогает.
- [x] Публикация: фото или альбом, подпись с хэштегами района и номером объекта, Telegraph-страница, «На карте» с приблизительной точкой, «Записаться на просмотр», снятие и обновление публикации.
- [x] Заявки клиентов с антиспамом. Атомарное «Взять клиента». Контакты видят только назначенный риелтор и владелец. Статусы, назначение времени просмотра, заметки, переназначение владельцем.
- [x] Сделки: мастер из 8 шагов, комиссия суммой или в %, связь с заявкой клиента, автостатус объекта и архив, поздравление в «Сделки», редактирование и отмена владельцем.
- [x] Статистика: общая, по риелторам, личная (только своя), за любой период, по валютам.
- [x] Ежедневные отчеты: запрос в 22:00 (настраивается), форма из 7 пунктов, сводка владельцу, статус «❌ Отчет не предоставлен», идемпотентная рассылка, cron-эндпоинты.
- [x] Архив без физического удаления, возврат из архива.
- [x] Webhook с secret token, health-check, ожидание БД при старте, graceful shutdown, безопасные вызовы Telegram API, логирование без персональных данных.
- [x] Alembic-миграции, Render Blueprint, 33 автотеста (включая гонку за заявку на PostgreSQL).

## 13. Что требует ручной настройки или интеграции

* **Создать бота** у @BotFather, получить `BOT_TOKEN`, задать `OWNER_ID`.
* **Рабочий чат и канал:** создать, добавить бота администратором, указать ID (п. 8–10).
* **Парсеры OLX и DOM.RIA** написаны по известной структуре страниц и проверены на сохраненной разметке. Живые страницы из среды разработки были недоступны. Сайты меняют верстку и могут блокировать запросы с IP дата-центров (Render). В таком случае бот честно сообщит об ошибке и предложит добавить объект вручную. После первого деплоя проверьте импорт на 2–3 реальных ссылках. Для стабильного импорта OLX и DOM.RIA позже можно подключить их официальные API (DOM.RIA требует ключ) отдельным парсером.
* **Словарь районов** для автоопределения (`KNOWN_DISTRICTS` в `bot/services/parser_service.py`) заполнен для Днепра. Для другого города его нужно дополнить.
* **Карта:** ссылки ведут на Google Maps. Координаты есть только у объектов, где их отдал сайт (OLX), или если их ввели вручную (поле «Координаты»). Геокодирование адреса не подключено.
* **Telegraph:** аккаунт создается автоматически. Если telegra.ph недоступен, публикация выйдет без кнопки «Подробнее».
* **Отчеты на засыпающем плане Render** требуют Cron Job (п. 6).
* **Роль admin** есть в модели, но пульт доступен только `OWNER_ID`, как требует ТЗ. Расширенные права для admin можно добавить отдельно.
* **FSM-диалоги** хранятся в памяти. При перезапуске незавершенное заполнение формы нужно начать заново (данные CRM не теряются). При необходимости можно подключить Redis-хранилище aiogram.
* **Расходы и бухгалтерия** из старой версии бота не переносились: в ТЗ их нет. Учитываются комиссии по сделкам.
